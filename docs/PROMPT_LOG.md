# 提交 ↔ Prompt 对照索引

> **用途**：把仓库里的每一次提交，对应到 `prompts/original/` 里的原始 AI 对话，让「代码演进链路」可追溯。
> **数据来源**：`git log --oneline` 与 `prompts/original/MANIFEST.md`。
> **判定原则**：只有提交内容与该次对话讨论的对象一致，才算「对应」；对不上就写「无对应记录」，不做推测性关联。

## 一、一个必须先说明的事实

仓库的前三个提交（`a836c97`、`3efa6ff`、`fa3a819`）是用旧目录快照**补录**的，作者时间不是开发时间。原因在 `ORIGINALITY.md` 里有完整披露：项目早期把开发目录搬来搬去，没有边写边提交，整理交付时才发现 Git 历史缺失，只能用快照补齐。

因此：

- **开发过程真实的证据是 `prompts/original/` 里的原始会话记录，不是提交时间戳。** 会话时间（10-16 ~ 10-26）才是真实开发节奏；
- 提交时间集中在 10-28 ~ 10-30，反映的是「整理与交付」的时间，不是「编码」的时间；
- 本表的价值在于**内容可追溯**，不在于时间连续。

## 五、怎么自己核一遍

```bash
git log --oneline            # 30 个提交
ls prompts/original/         # 4 个迭代的原始会话
cat prompts/original/MANIFEST.md   # 会话时间、条数、SHA-256
```

`prompts/original/raw/` 下的 jsonl 是**未改写的原始导出件**，字段只保留 `timestamp` / `role` / `text`；原始完整文件（含工具调用）保留在作者本机，可应评审要求提供。
